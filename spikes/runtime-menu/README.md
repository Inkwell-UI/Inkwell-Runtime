# Spike: runtime menu (milestone 0.0, spike 3)

Status: **FINAL (2026-10-23, SPIKES.md sections 1, 2). PARTIAL: local build PASS and in-game PASS (register / open / `LoadMovieEx`) on Skyrim SE 1.7.104; the GitHub Actions workflow was never run (nothing pushed).**

## Question

Can a minimal CommonLibSSE-NG SKSE plugin register and open one custom menu loaded from a JSON file, build in GitHub Actions on Windows, and stay runtime-agnostic (SE 1.5.97 / AE incl. 1.7.104 / GOG)?

## What was built

`Inkwell.dll` (`src/main.cpp`, ~250 lines):

- On `kDataLoaded`, reads `Data/SKSE/Plugins/Inkwell/menus/*.json` (nlohmann-json). A malformed file is logged and skipped. Schema: `{"name","swf","flags":{"pausesGame","cursor","modal"},"trigger":{"hotkey":<DIK>}}`, plus optional `depth` (the spec lists it as a menu field).
- Registers each menu with `RE::UI::Register(name, creator)`. The creator is a context-free function pointer, so there is one template slot per menu (max 8 in the spike).
- `InkwellMenu : RE::IMenu` sets `menuFlags`/`depthPriority`/`inputContext`, calls `BSScaleformManager::LoadMovieEx`, then logs the result, whether `_root` exists, and installs `_root.inkwellTrace(...)` so the SWF can call into C++ and be logged.
- A `BSInputDeviceManager` sink opens the menu on the hotkey (`UIMessageQueue::AddMessage(name, kShow)`) and closes it with the same key or Esc (`kHide`). It ignores the key while the console or main menu is open.
- Logs everything (trace level) to `Documents/My Games/Skyrim Special Edition/SKSE/Inkwell.log` (the SKSE-provided log directory, file named after the plugin), including the game runtime and SKSE versions.
- `SKSEPlugin_Version` is generated by CommonLibSSE-NG's `add_commonlibsse_plugin`: Address Library (post-AE) declared, `StructCompatibility::Independent`, no runtime version listed. Generated file: `build/__InkwellPlugin.cpp`.
- The product name is set once, in `CMakeLists.txt` (`INKWELL_PRODUCT_NAME`); C++ reads it as a macro.
- `test-assets/menus/inkwell_spike_{a,b,c,d}.json` open `InkwellSpikeA/B/C/D` (SWFs come from the ffdec-compile spike) on hotkeys O (24), P (25), L (38) and K (37). The old single `inkwell_spike.json` (hotkey O) was removed because it collided with A.

## Build

Needs VS 2022, CMake 3.21+, git, and vcpkg.

```powershell
git clone https://github.com/microsoft/vcpkg C:\dev\vcpkg
git -C C:\dev\vcpkg checkout 23b8a8e7409c2d6346114a88e834165bde79a51c
$env:VCPKG_ROOT = "C:\dev\vcpkg"
cd spikes\runtime-menu
cmake --preset release
cmake --build --preset release
# -> build\Release\Inkwell.dll
```

The first configure installs the vcpkg packages (~1.5 min) and compiles CommonLibSSE from source (~15+ min locally). In GitHub Actions the CommonLib prebuilt bundle is used automatically when it matches the toolset.

## In-game test script (author)

1. Copy to the game (MO2 mod or `Data/`), keeping these relative paths:
   - `SKSE/Plugins/Inkwell.dll`
   - `SKSE/Plugins/Inkwell/menus/inkwell_spike_a.json` (and `_b`, `_c`, `_d`; from `test-assets/menus/`)
   - `Interface/InkwellSpikeA.swf` (and B, C, D; from the ffdec-compile spike)
2. Make sure Address Library for SKSE Plugins is installed. Start the game through `skse64_loader.exe`.
3. Load a save (or reach the main menu, then load). Do not open the console yet.
4. Press **O** (DIK 24; **P**=25 for B, **L**=38 for C, **K**=37 for D). Expected: the menu opens (game pauses, cursor appears if the flags say so). The SWF content shows.
5. Press **O** again: it closes. Open it again and press **Esc**: it closes (if the pause menu also opens, note it).
6. If the SWF calls `_root.inkwellTrace("hello")`, the log shows `[AS2] inkwellTrace(hello)`.
7. Quit the game. Send back `Documents/My Games/Skyrim Special Edition/SKSE/Inkwell.log` and `skse64.log` (same folder), and say what you saw at steps 4 and 5 (nothing / black / SWF / crash).

What the log should show: runtime version line, `kDataLoaded`, `loaded menu 'InkwellSpikeA'`, `UI::Register ... done`, `input sink registered`, then on the key press `key 24 -> show`, `creator invoked`, `LoadMovieEx returned true`, `_root exists: true`.

## Result

| Check | Status |
|---|---|
| Local build (VS 2022 + cmake, Release) | **PASS**: `build\Release\Inkwell.dll` 737,280 B (720 KiB); exports `SKSEPlugin_Load/Query/Version`; version data `AddressLibrary` + `StructCompatibility::Independent`. First build ~15 min (CommonLib from source; reported, not re-measured). |
| In game (Skyrim SE 1.7.104, Steam) | **PASS** (Inkwell.log, skse64.log): `UI::Register('InkwellSpikeA') done` (x3 menus registered), `key 24 -> show`, `key 1 -> hide` (Esc), `menuFlags=0x41D`. Creator to `LoadMovieEx` return 2-4 ms; key press to return 2-59 ms. 8-menu cap (one template slot per menu). |
| `swf` path convention | **Finding:** `LoadMovieEx` wants a bare name and adds `Interface/` and `.swf` itself: `name='InkwellSpikeA'` -> `url='Interface/InkwellSpikeA.swf'`. A full `Interface/X.swf` returned false in an earlier run (log overwritten; reported by the spike). The `Interface/Exported/` fallback is from code reading only. The menu JSON `swf` must therefore be relative to `Interface/` without extension (or the runtime normalises). |
| GitHub Actions workflow `.github/workflows/runtime-spike.yml` | **UNVERIFIED**: never run, not pushed. YAML parses. |

Not explained: the `autoOpenSeconds` fallback never fired (no `scheduled` line); the first run had no key logs.

## Known risks and guesses to check in game

- `swf` path convention: resolved, see Result (bare name; the spike runtime normalises the JSON `swf` value (strips `Interface/` and `.swf`) before calling `LoadMovieEx`; the spec must pick one convention).
- Flag mapping from `pausesGame`/`cursor`/`modal` to `UI_MENU_FLAGS` and `inputContext` is a first guess (the in-game log shows `menuFlags=0x41D`; the behaviour of each flag was not individually checked).
- Esc may also trigger the vanilla pause/journal; not handled in the spike.
- The `_root.inkwellTrace` function is installed right after load; code running in the SWF's first frame may run before it exists.
- Max 8 menus (template slots); the final runtime needs a different approach.
